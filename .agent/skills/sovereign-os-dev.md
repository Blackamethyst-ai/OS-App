# Sovereign OS Development Skill

## Purpose
This skill enables Claude to work effectively on the Sovereign OS project - an AI-native operating system interface built with React, TypeScript, and Gemini AI. Claude should deeply understand the architecture, conventions, and philosophy to ship code immediately without exploration overhead.

## Project Identity

**Sovereign OS** is not a typical web app. It's an AI-native operating system interface where:
- AI is the primary interaction layer, not an add-on
- Multiple specialized agents collaborate on tasks
- The system can evolve itself through the Self-Evolution Protocol
- Voice is a first-class input method via Gemini Live API
- Everything is designed for cinematic, premium visual experience

## Architecture Overview

### Core Stack
- **Framework**: React 18+ with TypeScript (strict mode)
- **State**: Zustand with slice pattern (`store.ts` is the source of truth)
- **Styling**: Tailwind-style utility classes, custom CSS
- **Animation**: Framer Motion for all transitions
- **AI Backend**: Google Gemini API (2.0 Flash for speed, 2.5 Pro for reasoning)
- **Voice**: Gemini Live API for real-time voice, ElevenLabs for synthesis
- **Storage**: IndexedDB via `neuralVault` for persistence

### File Organization
```
/components/        → UI components (each is self-contained)
/components/autogen/ → Self-evolved components (generated by AI)
/services/          → Business logic, API clients, singletons
/hooks/             → React hooks for shared logic
/stores/            → Additional state stores beyond main store.ts
/types.ts           → All TypeScript interfaces
/store.ts           → Main Zustand store (~900 lines)
```

### Key Files To Check First
When starting work, always scan:
1. `store.ts` lines 1-150 → Current state shape
2. `services/geminiService.ts` lines 1-50 → SOVEREIGN_SYSTEM_INSTRUCTION
3. `services/geminiService.ts` HIVE_AGENTS → Agent definitions

## Design Principles

### Visual Language
- **Cinematic**: Every interaction should feel like a sci-fi interface
- **Dark-first**: Deep blacks (#0a0a0c), subtle glows
- **Accent colors**: Purple (#9d4edd), Cyan (#22d3ee), Amber (#f59e0b)
- **Typography**: Font-mono for data, font-black for emphasis, uppercase + tracking-widest for labels
- **Glass effects**: backdrop-blur-xl, subtle borders (border-white/10)

### Animation Patterns
```tsx
// Standard entry animation
initial={{ opacity: 0, y: 20 }}
animate={{ opacity: 1, y: 0 }}
exit={{ opacity: 0, y: -20 }}

// Glow effect for active states
className="shadow-[0_0_30px_rgba(157,78,221,0.3)]"

// Pulse for live/active indicators
className="animate-pulse"
```

### Component Conventions
- Use `cn()` utility for conditional classes
- All components use functional style with hooks
- Props interfaces defined inline or in types.ts
- JSDoc comments for complex logic
- Self-contained: component includes its own styles

## Code Patterns

### Store Updates
```typescript
// Always use the actions pattern
const { actions } = useAppStore();
actions.setProcessState({ isLoading: true });
actions.addLog('SUCCESS', 'Operation complete');
```

### API Calls
```typescript
// Always check for API key first
if (!apiKeyService.hasGeminiKey()) {
  await promptSelectKey();
  return;
}

// Use try/catch with proper error handling
try {
  const result = await generateText(prompt, model);
  // handle success
} catch (error) {
  actions.addLog('ERROR', `Failed: ${error.message}`);
}
```

### New Components
When creating components:
1. Start with the interface/props
2. Add motion wrappers for animation
3. Use the color system (THEME.accent.*)
4. Include proper TypeScript types
5. Handle loading/error states

## Self-Evolution Protocol

The OS can generate its own components:

1. **Friction Detection**: `selfEvolution.ts` monitors errors, repeated actions
2. **Code Generation**: Gemini generates React/TypeScript
3. **Approval**: User approves in Evolution Console
4. **Deployment**: Approved code saved to localStorage
5. **File Write**: Claude writes to `/components/autogen/`
6. **Hot Reload**: Vite picks up new file

### Deploying Evolutions
When user says "deploy evolutions":
1. Check localStorage key: `evolution_pending_deployments`
2. Read the pending evolution objects
3. Write each to `/components/autogen/[fileName]`
4. Call `selfEvolution.markDeployed(id)` equivalent action

## Voice Core Architecture

- **VoiceManager.tsx**: Orchestrates Gemini Live sessions
- **VoiceMode.tsx**: UI for voice interaction
- **LiveSession class**: In geminiService.ts, handles streaming
- **Hot-swap**: Changing agent triggers disconnect/reconnect cycle
- **Fallbacks**: Avatar generation has fallback on rate limits

## What NOT To Do

- ❌ Don't use `any` type without comment explaining why
- ❌ Don't create components without animation
- ❌ Don't hardcode colors - use the theme system
- ❌ Don't skip error handling
- ❌ Don't make API calls without checking for key first
- ❌ Don't create oversized files - split at 500 lines

## Execution Mode

When working on this project:
1. **Ship working code first** - iterate after
2. **Check types compile** - run `npx tsc --noEmit` before committing
3. **Commit frequently** - small, focused commits
4. **Push to git** - user expects changes synced
5. **Explain tradeoffs** - don't silently make architectural decisions
